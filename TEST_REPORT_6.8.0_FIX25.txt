USTALONA PRZYCZYNA BŁĘDU PRODUKCYJNEGO
Log FIX24 zwracał HTTP 503 na etapie login-password-kdf. Kod session.js i reset.js żądał PBKDF2 z 210000 iteracji. Cloudflare Workers WebCrypto odrzuca wartości powyżej 100000 iteracji jako NotSupportedError. To wyjaśnia, dlaczego błąd występował przed porównaniem hasła, również przy fikcyjnym adresie .invalid.

- Nowe sole mają wersjonowany format pbkdf2-sha256$100000$ oraz 16 bajtów losowej soli.
- Test negatywny nieistniejącego konta zwraca HTTP 401 LOGIN_FAILED zamiast HTTP 503.
- Rejestracja testowa: HTTP 201.

WAŻNE O STARYCH HASHACH
Wcześniejszy format soli był niewersjonowany i był tworzony przez kod żądający 210000 iteracji. Jeśli w bazie istnieją hashe utworzone poza Cloudflare w tym formacie, Worker nie może ich zweryfikować przez WebCrypto. Takie konto wymaga resetu hasła. Rekord konta i sesje nie są kasowane przez tę poprawkę. Reset ustawia nowy format FIX25. Działanie resetu przez e-mail wymaga skonfigurowanej usługi Resend.

OGRANICZENIA WERYFIKACJI
- Testy wykonano lokalnie na Node.js v22.16.0; komputer użytkownika ma w logach Node.js v24.19.0.
- Test Cloudflare został zasymulowany przez wrapper WebCrypto odrzucający PBKDF2 >100000; nie był to request do produkcyjnego Cloudflare.
- Nie wykonano publikacji FIX25 ani nie zmieniano produkcyjnej bazy D1 w tej sesji.
- Rzeczywiste logowanie i e-mail resetu trzeba sprawdzić po publikacji.
- 100000 iteracji jest zgodnością z limitem Workers, nie docelowym maksimum odporności KDF; dalsza poprawa wymaga KDF obsługiwanego w tym runtime i zweryfikowanego pod jego limity.
