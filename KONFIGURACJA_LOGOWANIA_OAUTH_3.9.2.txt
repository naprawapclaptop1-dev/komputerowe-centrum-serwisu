AKADEMIA SERWISU PRO 3.9.2 — KONFIGURACJA LOGOWANIA SPOŁECZNOŚCIOWEGO

Ważne: kod logowania jest przygotowany, ale Google/Facebook/Microsoft nie zaczną działać, dopóki właściciel nie utworzy aplikacji OAuth u dostawcy i nie zapisze własnych kluczy jako sekretów Cloudflare Pages. Nie umieszczamy Client Secret w HTML, JavaScript ani w ZIP.

ADRES CALLBACK (ustaw identycznie u każdego dostawcy):
https://naprawa-pc-akademia-serwisu-pro.pages.dev/api/auth/callback

W Cloudflare Pages -> projekt naprawa-pc-akademia-serwisu-pro -> Settings -> Variables and Secrets -> Production dodaj:

GOOGLE_CLIENT_ID
GOOGLE_CLIENT_SECRET
FACEBOOK_CLIENT_ID
FACEBOOK_CLIENT_SECRET
MICROSOFT_CLIENT_ID
MICROSOFT_CLIENT_SECRET

Opcjonalnie:
FACEBOOK_GRAPH_VERSION = v26.0
MICROSOFT_TENANT_ID = common

Można też dodać sekrety przez Wrangler (w katalogu projektu, z lokalną konfiguracją i zalogowanym Wrangler):
wrangler pages secret put GOOGLE_CLIENT_ID --project-name naprawa-pc-akademia-serwisu-pro
wrangler pages secret put GOOGLE_CLIENT_SECRET --project-name naprawa-pc-akademia-serwisu-pro
wrangler pages secret put FACEBOOK_CLIENT_ID --project-name naprawa-pc-akademia-serwisu-pro
wrangler pages secret put FACEBOOK_CLIENT_SECRET --project-name naprawa-pc-akademia-serwisu-pro
wrangler pages secret put MICROSOFT_CLIENT_ID --project-name naprawa-pc-akademia-serwisu-pro
wrangler pages secret put MICROSOFT_CLIENT_SECRET --project-name naprawa-pc-akademia-serwisu-pro

Google:
- Utwórz OAuth Client typu Web application.
- Dodaj powyższy callback do Authorized redirect URIs.
- Włącz OpenID Connect (openid, profile).

Facebook:
- Dodaj produkt Facebook Login (Web).
- Dodaj powyższy callback do Valid OAuth Redirect URIs.
- Ustaw poprawną domenę serwisu w ustawieniach aplikacji.

Microsoft:
- Zarejestruj aplikację w Microsoft Entra ID.
- Dodaj platformę Web i powyższy Redirect URI.
- Wybierz typ kont zgodny z polityką aplikacji; domyślny tenant Akademii to common.

Po zapisaniu sekretów wykonaj jedno wdrożenie Pages, aby Functions otrzymały sekrety. API /api/auth/status pokaże tylko wartości true/false, nigdy same klucze.

DO CZASU KONFIGURACJI SSO:
- Profil pseudonimowy w Akademii działa bez logowania Google/Facebook/Microsoft.
- Autor może wysyłać przypadki do moderacji.
- Synchronizacja historii nauki pozostaje osobną, dobrowolną zgodą.

MODERACJA WIEDZY SPOŁECZNOŚCI
W Cloudflare Pages -> naprawa-pc-akademia-serwisu-pro -> Settings -> Variables and Secrets -> Production ustaw także:
ADMIN_REVIEW_TOKEN

Wygeneruj długi losowy token lokalnie (nie używaj przykładu ani publicznego hasła):
node -e "console.log(require('crypto').randomBytes(32).toString('base64url'))"

Zapisz wynik jako sekret ADMIN_REVIEW_TOKEN w Cloudflare Pages. Następnie w Akademii, w zakładce „Moje konto i historia”, wprowadź ten sam token w panelu „Panel opiekuna wiedzy”. Token jest przesyłany tylko jako nagłówek Authorization i nie jest zapisywany w przeglądarce. Nie umieszczaj go w HTML, plikach JS, ZIP ani repozytorium.

WAŻNE O STANIE LOGOWANIA
- Przyciski Google/Facebook/Microsoft są celowo nieaktywne, dopóki odpowiedni dostawca nie ma ustawionych obu sekretów (Client ID i Client Secret).
- Po zapisaniu sekretów wykonaj publikację Pages, aby Functions otrzymały konfigurację.
- Profil pseudonimowy i wysyłanie zgłoszeń do moderacji działają niezależnie od OAuth.
