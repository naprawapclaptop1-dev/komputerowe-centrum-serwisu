FIX186 — BEZPIECZEŃSTWO, PRYWATNOŚĆ I GRANICE DZIAŁANIA
=======================================================

IMPORT LOGÓW
------------
Importer obsługuje tekstowe eksporty CSV/XML/JSON/TXT. Pliki są czytane lokalnie
w przeglądarce i ograniczone rozmiarem. ETL i EVTX są formatami binarnymi i wymagają
konwersji przez narzędzia Windows. Ślady mogą zawierać nazwy użytkowników, procesów,
ścieżki plików, nazwy hostów i szczegóły środowiska. Przed udostępnieniem usuń dane
wrażliwe i uzyskaj zgodę właściciela komputera.

AI — PRZYPADKI I PCB
--------------------
Generator przypadków używa istniejącego endpointu /api/chat; klucz Gemini nie trafia
do JavaScript przeglądarki. Backend waliduje zakres urządzeń i wykorzystuje istniejące
limity/konfigurację. Analiza PCB jest oddzielną operacją: dopiero checkbox zgody i
kliknięcie użytkownika powodują wysłanie obrazu do Google Gemini. Obrazy nie są
zapisywane w D1 ani localStorage. Użytkownik powinien wcześniej przyciąć etykiety,
numery seryjne i dane klienta. AI nie potwierdza zwarć, napięć ani usterek ukrytych.

FIRMWARE
--------
Porównanie SHA-256 z zaufanym hashem OEM jest kontrolą zgodności zawartości z podaną
wartością, a nie samodzielnym dowodem autentyczności źródła. Authenticode i SignTool
weryfikują obsługiwane pliki/katalogi. Uniwersalny skrypt nie weryfikuje podpisu
wewnętrznego payloadu każdej kapsuły UEFI. Nie ma flashowania ani zapisu firmware.

KOLEKTOR WINDOWS
----------------
Kolektor prosi o UAC i uruchamia tylko zbieranie/eksport diagnostyki oraz weryfikację
pliku. Nie wykonuje Repair-Volume, SFC, DISM naprawczego, flashowania ani kasowania.
Wymaga Windows PowerShell 5.1 i odpowiednich narzędzi systemowych (WPR, tracerpt,
StorDiag, Get-WinEvent); SignTool jest opcjonalny i wymaga Windows SDK/WDK.

DANE I POSTĘPY
--------------
Nie dodano D1, tabel ani migracji. Surowe logi i zdjęcia nie są zapisywane przez panel
w D1 ani localStorage. Postęp panelu FIX186 jest zapisywany lokalnie pod osobnym
kluczem localStorage; nie jest to synchronizacja konta między urządzeniami.

TESTOWANIE
----------
Testy Node.js potwierdzają parsery, walidację, endpoint, zgodę, metadane i integrację.
W środowisku budującym nie było Windows PowerShell, dlatego nie można twierdzić, że
kolektor został wykonany na prawdziwym Windows 10/11. To wymagane do weryfikacji
WPR/StorDiag na komputerze użytkownika. Publikacja Cloudflare również wymaga logu.
