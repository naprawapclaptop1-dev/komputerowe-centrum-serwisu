KOMPUTEROWE CENTRUM SERWISU — FIX076

Naprawa przyczyny błędu z logu FIX075:
- Windows PowerShell 5.1 z $ErrorActionPreference=Stop traktował stderr programu gh.exe jako terminating ErrorRecord. Przez to gh auth status kończył cały skrypt zanim uruchomił automatyczne logowanie.
- Dodano Invoke-NativeCapture oraz Invoke-NativeInteractive, które tymczasowo ustawiają ErrorActionPreference=Continue tylko na czas wywołania programu natywnego, zawsze odczytują $LASTEXITCODE i przywracają poprzednią wartość.
- Przy braku sesji skrypt automatycznie uruchamia gh auth login --web --git-protocol https --hostname github.com --scopes repo,workflow. Użytkownik jednorazowo zatwierdza dostęp w przeglądarce; główny CMD nie przekierowuje wyjścia tego etapu do pliku, więc kod urządzenia pozostaje widoczny; następnie ten sam przebieg kontynuuje synchronizację.
- Po autoryzacji wykonywane jest gh auth setup-git, odczyt konta i kontrola permissions.push dla przypisanego repozytorium.
- Wydawca GitHub Releases korzysta z identycznej bezpiecznej obsługi stderr i kodów wyjścia.
- Główny CMD sprawdza marker FIX076, pokazuje rzeczywistą ścieżkę uruchomienia i informuje o jednorazowym logowaniu.
- Dodano testy statyczne FIX076 i rejestrację ich w CHECK_SOURCE.cmd. Workflow GitHub Pages używa actions/checkout@v7.
- Zachowano zasadę: jeden ZIP, jeden CMD, jedno repozytorium dla tego programu; brak force push, --clobber i nadpisywania opublikowanych wydań.

Wersja aplikacji desktopowej pozostaje 1.0.0.69. FIX076 dotyczy automatyzacji logowania i publikacji.
Weryfikacja w tym środowisku: test ZIP i kontrole statyczne. Nie wykonano natywnego testu Windows PowerShell 5.1 ani publikacji GitHub.
