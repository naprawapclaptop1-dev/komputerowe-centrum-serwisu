NAUKA OD A DO Z — RAPORT FIX101

Problem wejściowy:
Uruchamiacz FIX100 zakończył się kodem 10 i komunikatem „Nie wykryto działającego Node.js”, mimo że wcześniejsze uruchomienie projektu raportowało Node.js v24.19.0.

Diagnoza:
Resolver FIX100 polegał na osobnym procesie PowerShell uruchamianym z -NoProfile. Nie dawał użytkownikowi sposobu wskazania pliku, jeśli Node był dostępny tylko przez profil/środowisko innego terminala albo w niestandardowej lokalizacji. Sam opis rozległego skanowania nie gwarantował znalezienia pliku na konkretnej maszynie.

Zmiana FIX101:
- CMD-first discovery: bieżący PATH i where.exe bez PowerShell.
- Zapamiętana ścieżka NODE_EXE.path oraz zmienne NODE_EXE/NODE_HOME/NODEJS_HOME.
- Dodatkowe katalogi instalatora, WinGet i menedżerów wersji.
- PowerShell jako wyszukiwanie uzupełniające.
- Interaktywne okno wyboru node.exe lub ręczne przeciągnięcie/wklejenie pełnej ścieżki.
- Weryfikacja każdego pliku przez --version i zapis poprawnie zweryfikowanej ścieżki w katalogu projektu.
- Tymczasowe rozszerzenie PATH dla procesu startowego; bez trwałych zmian systemowego PATH lub rejestru.
- Zachowane stare skróty FIX100 jako przekierowania do FIX101.

Wyniki testów:
- FIX99/FIX100 regression: 143/143 PASS.
- FIX101 tests: 13/13 PASS.
- Razem: 156/156 PASS.
- JavaScript syntax checks: 6/6 PASS.

Środowisko:
Node.js v22.16.0, Linux. Nie wykonano rzeczywistego uruchomienia Windows CMD / PowerShell 5.1 ani okna wyboru pliku — tych elementów należy dokonać na komputerze docelowym.

Wersje:
Produkt 6.8.0; hotfix narzędzi Windows FIX101; runtime zdjęć FIX99.

Bezpieczeństwo:
Nie wykonano publikacji Cloudflare Pages, migracji D1, zmian schematu ani danych użytkowników. Nie zmieniono systemowego PATH ani wpisów rejestru Windows.
